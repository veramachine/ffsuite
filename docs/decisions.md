# ffman: decisions

Copied from nixos-config's `.agents/docs/07-tools.md`, its `## ffman` section, at
`253c5eb`; that file's history stays there.

ffman, in Python 3.13: [`README.md`](../packages/ffman/README.md) for
using it, [`AGENTS.md`](../AGENTS.md) for working on it, the plan
in [`docs/ffman-python.md`](ffman-python.md), the command line's contract
in [`docs/ffman-spec.md`](ffman-spec.md). One command today, `convert`;
`concat` and `transcribe` are planned. Packaged by this repository's flake
(`nix/packages.nix`), `nix run github:veramachine/ffsuite`; its overlay builds it on another nixpkgs
(a system's ffmpeg-full, FDK and all). Its checks (`nix/checks.nix`), each on Python 3.13 and
3.14: `tests` (the suite, 100% line and branch), `matrix` (the combination matrix, `pytest -m
slow`), `types` (basedpyright), `vulture`, `installed` (the built binary through its wrapper
alone); `lint` once (ruff, nixfmt, shellcheck). It replaced the bash `tools/ffman.sh`
(nixos-config's, at its tag `ffman-bash-final`; removed in phase 5), after equalling it on
every invocation of the bash suites; those suites live on as its tests. Both
paths pass on the pinned ffmpeg 8.1.2: FDK, and native aac through the test hook
`FFMAN_NO_FDK=1`. **Needs ffmpeg ≥ 7**: `-enc_time_base:v demux` (below) is not
in 6.x.

**Which ffmpeg.** Inside the system `ffmpeg-full` is the tuned build (FDK); as a
flake output it is stock. `ffman` must work on both (the rule above `sax`), so
it detects `libfdk_aac` at run time and falls back to native `aac`; `convert`
uses a native-aac twin of the `youtube-aac` preset. The flake check runs on the
stock build, i.e. the fallback path.

**Packaging.** The wrapper sets `PATH` (`runtime`, `nix/packages.nix`: what ffman runs, and
nothing else). ffman carries its fonts (6.7.3): IBM Plex Sans Regular and Bold, the captions', and IBM Plex Mono
Bold, the camcorder's stamp's (its one style, bold, no override), in `ffman/fonts/`, the 1.1.0
releases nixpkgs' `ibm-plex` fetches byte for byte (`sans` and `mono`: each `fetchzip` hash reproduced
by nix, the files `cmp`-equal; one licence text, identical), with IBM's OFL text. `jobs/convert/fonts.py` hands
libass that folder -- or `FFMAN_FONTS_DIR`'s, an override -- copied into the work directory where
its path holds what ffmpeg's filter syntax splits (a spaced venv) or a zip holds it; libass reads
`fontsdir` non-recursively, so the default font renders on hosts without it installed, even with
no fontconfig at all, as in the Nix builder (render bit-identical either way). It carries its
ffmpeg-normalize presets too, in `ffman/normalize/` -- an `XDG_CONFIG_HOME`
(`ffmpeg-normalize/presets/`): `youtube-aac`, YouTube's AAC upload spec -- loudness by EBU R128's measure
(loudnorm) to -14 LUFS, LRA 7, true peak -2; stereo (mono upmixed and 5.1 folded down before measuring, so the target
holds on the layout delivered), 48 kHz, AAC-LC (`aac_low`) at 384 kbps by FDK, ffmpeg's best
AAC encoder (Hydrogenaudio), with `-cutoff 20000` (its CBR default is 17 kHz at 96 kbps a
channel and more, 20 kHz its maximum); `+faststart`, no edit list (ffmpeg writes one for AAC's
delay unless told not to) -- and its native twin for an ffmpeg without FDK (`aac`, the one
difference). `jobs/convert/carried.py` hands over both folders alike: the package's own, or a
copy in the work directory where a zip holds it; `FFMAN_NORMALIZE_HOME`, set, is used instead.
So a pip install normalises as the Nix package does (the owner's decision, for PyPI: the
flake's built folder, 6.7.7's, retired; its JSON kept value for value, `nix eval` of the
retired file). nixos-config's home keeps its own file -- the two apart, never checked equal
(the owner's decision, 6.7.7).

**Platforms.** POSIX's: ffman starts each tool in its own process group and stops the group
(`subprocess`'s `process_group`, `os.killpg`: POSIX's alone, Python's documentation) on SIGINT,
SIGTERM and SIGHUP (SIGHUP, SIGKILL, SIGPIPE: Unix's). Windows has none of them, nor `env`; its
absolute paths (`C:\`) are no filter-safe path; ffmpeg-normalize reads `%APPDATA%` there. So
`ffman/__main__.py`, the command's entry, refuses Windows before importing any module that
names them -- else a traceback (shown: SIGHUP removed, the import fails) -- and points to WSL,
a Linux. The flake: Linux (x86_64, aarch64) and Apple silicon (aarch64-darwin: every runtime
tool available there, evaluated; nixpkgs 26.05 the last to support Intel Macs, until December
2026); the checks read the process table through `ps` (nixpkgs' `unixtools.ps`: procps, or
macOS's adv_cmds), not `/proc`. The image (`nix/image.nix`, `dockerTools.streamLayeredImage`,
Linux's): ffman and its runtime, tini as PID 1, `/tmp`, on ffmpeg-full with FDK (`withUnfree`,
as the owner's system) -- built for the owner, never published: ffmpeg's configure makes a GPL
build with libfdk_aac "nonfree and unredistributable" (the owner's decision). `overlays.default`
gives the same image as `ffman-image`, on the consumer's ffmpeg-full: a system's tuned build, the
store path it already has.
